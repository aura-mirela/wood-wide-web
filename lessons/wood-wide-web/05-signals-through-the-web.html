Lesson 05 — Signals through the web

Episodes 5–6: Connect the trees & watch the exchange. Click a node, a pulse travels the network to the trees; then nutrients flow both ways — sugar down from the tree (photosynthesis), water and minerals up from the fungus.

Concepts

  • A pulse is a moving window over aDistance. Everything you need was baked in lesson 04: 
    pulse = smoothstep(uFront - uWidth, uFront, aDistance)
      * (1.0 - step(uFront, aDistance))
    — brighten where aDistance is just behind uFront, advance uFront each frame. No geometry touched, no CPU work. Multiple pulses = small uniform array, loop in the shader.
  • Direction matters. aDistance grows root→tips, so an advancing front is fungus→outward. For tree→fungus flow you run a front backwards. If you want per-click origins (pulse starts at the clicked node, not the root), bake a second attribute: distance from that node — or simpler, precompute distances from each clickable node and store the 2–3 you need as separate attributes.
  • Nutrient particles on curves. The exchange is slower and more material than the light pulse: small glowing particles crawling along the hypha curves. You already have each branch as a CatmullRomCurve3 — sample curve.getPointAt((t * speed + offset) % 1) for N particles per branch. CPU-updating a few hundred of these in useFrame is fine (write into an InstancedMesh or a Points position buffer). Two populations, two colors, opposite directions: blue-white sugar flowing down, warm amber minerals flowing up — exactly the storyboard's two-tone exchange.
  • Tree roots join the party. Give each tree from lesson 01 a short root fan (same growth algorithm, grown downward/inward toward the nearest network node). Where root meets node, place a brighter junction glow. This is the "the forest is one organism" shot, so spend polish here.
  • Teaching UI. This episode carries the actual science. Panels:
    • node click → small anchored label ("Mycelium — the underground network that connects the forest")
    • exchange view → a fixed legend card: Tree → Fungi: sugars (photosynthesis) / Fungi → Tree: water & minerals (from the soil), as in the inspiration.
    • UX rule: one concept on screen at a time. Panels appear when their subject becomes visible and get out of the way after.

Build steps

  1. Make nodes (from lesson 04) clickable: small invisible-ish sphere colliders at node positions with onClick; hover = node brightens + cursor pointer.
  2. Implement the single-pulse shader against aDistance. Click → set uFront = 0, advance in useFrame with slight ease-out; fade the tail.
  3. Extend to 3–4 simultaneous pulses (uniform arrays uFronts[4]). Overlapping pulses should add, then clamp — saturation at crossings looks electric.
  4. Root fans per tree + junction glows where they meet the network.
  5. Nutrient particle system along branch curves, two directions, two colors. Start with one branch, then all. Profile before optimizing.
  6. The legend / info panels, with entrance–exit transitions consistent with lesson 02's card (one shared Panel component by now).
  7. Sound hook (optional but Halloween-worthy): a soft sub-bass whoosh on pulse send. Even a single sample changes the feel completely.

Exercises

  • Make pulse speed natural: constant speed in world units means uFront advances linearly in aDistance — verify a pulse doesn't visibly accelerate on long straight branches vs twisty ones. If it does, your aDistance is per-segment-count, not per-length. Fix it.
  • When a pulse reaches a tree, make the tree respond: canopy glow blooms for a second (lerp a uniform on the tree material). Cause and effect must be legible.
  • Click-anywhere ambient mode: tiny automatic pulses fire every few seconds from random nodes so the network never looks dead while the user reads panels.

Checkpoint

  • Write the moving-window pulse expression from memory and explain each term.
  • Why do light pulses live in the shader but nutrient particles on the CPU? What property of each makes that split right?
  • How would you implement "pulse starts at clicked node" efficiently, and what's wrong with recomputing graph distance in JS on every click? (Is anything?)

Quiz

1. The pulse travels through the network geometry without touching it on the CPU because:

The moving-window trick: all data static, one scalar uniform animates everything.

2. A pulse visibly speeds up on twisty branches. The bug is:

Equal aDistance steps must mean equal world-space millimeters, or speed depends on sampling density.

3. Nutrient particles crawl along branches on the CPU (sampling getPointAt) rather than in the shader because:

Right tool for scale: hundreds of exact curve-followers = trivial CPU work; thousands of loose glows = shader.

4. Two simultaneous pulses cross on a shared branch. With additive brightness you should:

Physical honesty aside, crossings are a storytelling gift; clamp to avoid blowout.

5. UX: the sugar/mineral legend panel should appear:

One concept on screen at a time, synchronized with what the eye can currently verify.
