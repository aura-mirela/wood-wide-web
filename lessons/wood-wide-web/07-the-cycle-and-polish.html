Lesson 07 — The cycle & the whole story

Episodes 8–9: The cycle continues & reflection. A spore grows: mycelium → primordium → mushroom. Then the camera pulls back and the forest breathes as one. Finally: stitch all episodes into one continuous experience.

Concepts

  • Growth = one scalar. Every growth you need is already a technique you own:
    • spore → mycelium: aDistance < uGrowth reveal (lesson 04 exercise)
    • primordium → mushroom: lerp between two lathe profiles (same point count!) — profile A: a squat pin; profile B: the full Fly Agaric. Lerp in JS and rebuild, or better: pass both profiles' positions as attributes (aPosA, aPosB) and mix(aPosA, aPosB, uGrowth) in the vertex shader. Add a slight overshoot ease for the cap popping open.
    • growth should feel biological: not linear — slow start, surge, settle (an S-curve / smoothstep of smoothstep).
  • The episode state machine. The experience is a sequence: forest → mushroom → spores → ground → network → exchange → micro → cycle → reflection. Centralize it (React context or zustand):
    • current episode + a 0–1 progress within it
    • which inputs are live (click? scroll? drag?) per episode
    • camera mode and targets per episode
    • uniforms each episode drives (uDim, bloom strength, fog density)
    Components read this state; nothing reaches across components to poke a sibling. This is the difference between a demo and a piece.
  • Transitions are content. Define one transition grammar and reuse it: camera eases on curves (lesson 03), light states lerp (lesson 02), panels share one entrance/exit (lesson 02/05). The user should feel one hand guiding everything.
  • Reflection scene: wide shot, everything subtly alive at once — fireflies, faint network pulses under the soil, a new small mushroom where the spore landed. No UI except one line of text. Restraint is the skill being practiced.
  • Performance pass, in order: measure (r3f-perf or gl.info), then: merged geometries? instanced everything repeatable? Points for lights? textures sized sanely? postprocessing half-float? only then micro-optimize shaders. react-responsive / useMediaQuery to drop counts on mobile + dpr clamp on the Canvas.

Build steps

  1. Extract the state machine first — refactor existing episodes to read from it. Painful, instructive, worth it. Keyboard arrows = prev/next episode for debugging; a tiny episode indicator dev-overlay.
  2. The cycle scene: hero spore from lesson 06 lands on soil → mycelium spreads (your network growth, smaller scale, uGrowth driven) → primordium rises (profile lerp) → cap opens → a few spores release (lesson 03 system, reused). Entire sequence scrubbed by one 0–1 value. Scroll drives it.
  3. Reflection: pull-back camera curve to the widest shot; trigger the ambient systems; fade in the closing line ("The forest is more than what you see").
  4. Title & onboarding: opening text from episode 1, a hint system that shows input affordances ("drag to follow") only when the user stalls for ~5s.
  5. Full runthrough QA: play start-to-finish 10 times. Fix every camera jump, every panel overlap, every pop. Keep a BUGS.md; fixing polish bugs teaches more than building features.
  6. Performance pass as above. Target: 60fps desktop, stable 30+ on a mid phone.

Exercises

  • Record a screen capture of the full experience and watch it muted. Where does your eye get lost? That's where a light or motion cue is missing.
  • Swap the profile-lerp growth for a vertex-shader version if you did it in JS (or vice versa) and compare cost + code clarity.
  • Write a one-paragraph "how it works" for each episode from memory. Anything you can't explain, revisit.

Checkpoint

  • Why must both lathe profiles have the same point count to lerp? What breaks otherwise?
  • What belongs in the central state vs. local component state? Give one example of each from your own code.
  • Name the three cheapest big wins you found in your performance pass.

Quiz

1. Lerping between two lathe profiles requires the same point count because:

Morphing is per-index interpolation; same count and same ordering along the profile.

2. Doing the pin→mushroom morph with mix(aPosA, aPosB, uGrowth) in the vertex shader (vs rebuilding geometry in JS) buys you:

Geometry uploads every frame are the hidden cost of the JS version; the shader version animates for free.

3. Which belongs in the central episode state, not local component state?

Input routing is story-level orchestration; a, c, d are private to their components.

4. Growth that feels biological follows:

Smoothstep-of-smoothstep or similar; linear growth reads as mechanical.

5. First step of a performance pass:

Optimizing unmeasured code is guessing; the biggest win is usually draw calls, but prove it first.
