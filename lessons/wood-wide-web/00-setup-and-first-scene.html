Lesson 00 — Setup & first scene

Goal

A fullscreen dark canvas with one glowing test sphere whose color comes from a .glsl file you wrote, lit by nothing (emissive only), with orbit controls. Boring on purpose — this is the skeleton everything else hangs on.

Concepts

  • R3F is a renderer, not a wrapper. JSX like <mesh> and <sphereGeometry> creates real three.js objects. Props map to object properties (position, rotation, args for constructor arguments).
  • The render loop. useFrame((state, delta) => ...) runs every frame. state.clock.elapsedTime is your global time — you will pass it into almost every shader as a uTime uniform.
  • shaderMaterial lifecycle. A THREE.ShaderMaterial takes vertexShader and fragmentShader strings plus a uniforms object. Changing a uniform's .value is cheap (every frame is fine); recreating the material is expensive.
  • Why vite-plugin-glsl. It lets you import frag from './test.frag.glsl' and get a string, with #include support so you can share a noise function across shaders instead of pasting it everywhere.

Build steps

  1. Clean the Vite template: empty App.tsx, remove the demo CSS, give html, body, #root 100% height and a near-black background (#0a0a12).
  2. Render a <Canvas> with a camera at roughly [0, 2, 8], fov ~45.
  3. Add a <mesh> with sphereGeometry and a meshBasicMaterial first. Confirm you see it. Always get the dumb version on screen before the clever one.
  4. Create src/shaders/test.vert.glsl and src/shaders/test.frag.glsl:
    • vertex: standard projectionMatrix * modelViewMatrix * vec4(position, 1.0), pass uv to the fragment stage as a varying
    • fragment: color from uv plus a uTime uniform pulsing the brightness
  5. Swap the material for a <shaderMaterial> using those imports, and drive uTime from useFrame. Tip: hold the material in a useRef and update ref.current.uniforms.uTime.value.
  6. Add drei's <OrbitControls /> so you can inspect everything you build later.

Exercises

  • Make the pulse a function of uv.y so the sphere glows from the top down.
  • Break the vertex shader on purpose (multiply position by 0) and read the result. Knowing what "vertex shader is wrong" looks like saves hours later.
  • Add a second uniform uColor (vec3) and control it from a prop.

Checkpoint

  • What is the difference between an attribute, a uniform, and a varying?
  • Why does updating uniforms.uTime.value not re-render the React tree?
  • In what coordinate space is position inside the vertex shader?
