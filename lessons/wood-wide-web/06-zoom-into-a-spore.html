Lesson 06 — Zoom into a spore

Episode 7: Click a spore. Dive into the microscopic world — spores up close, textured and alive, floating in a hazy void. See how life continues.

Concepts

  • InstancedMesh properly. One geometry + one material + N transforms = one draw call. You set each instance's matrix once (setMatrixAt(i, matrix), then instanceMatrix.needsUpdate = true). For per-instance behavior (unique wobble phase, size, hue shift), add instanced buffer attributes (InstancedBufferAttribute) and read them in the vertex shader — same mental model as point attributes in lesson 03, but now on full geometry.
  • The spore itself, procedurally: an icosphere displaced by low-frequency fbm (lumpy organic silhouette) + high-frequency noise in the fragment for surface detail, fresnel glow membrane, interior "nucleus" faked with a darker center via normal/view tricks. One good shader × 30 instances with varied seeds = a living cloud where no two spores match.
  • Raycasting instances: R3F events on InstancedMesh give you event.instanceId. That's how "click a spore" works.
  • The scale transition (the hard, fun part). You cannot actually shrink the camera. Illusions that work, pick one:
    1. Dolly + fade (simplest). Fly the camera at the clicked spore (bezier from lesson 03), and as it fills the screen, crossfade (postprocessing or a DOM scrim) into a separate micro-scene group that was hiding at another location / on another layer.
    2. Nested scale trick. The micro-world already exists inside the spore's position but scaled tiny; camera flies "into" it while you scale the world group up around a pivot. Seamless, no cut — harder to keep stable.
    Start with 1. If it feels good, try 2 as an experiment.
  • Postprocessing is the microscope. @react-three/postprocessing: <Bloom> (you've earned it — all those emissives), <DepthOfField> with a shallow focus range (nothing says "microscopic" like razor-thin focus), <Vignette> (replaces your CSS one in 3D-land), subtle <Noise> for film grain. Postprocessing is also the crossfade mechanism for transition #1.

Build steps

  1. Micro-scene group: 20–40 instanced spores drifting in a dark amber haze (fog + big soft background gradient plane). Slow rotation + fbm bob per instance, driven by aSeed in the vertex shader — no CPU per-frame updates.
  2. Spore shader: displaced icosphere + fresnel membrane + varied hue per instance (aSeed → slight hue rotation). Verify variety: screenshot 5 spores, they should look like siblings, not clones.
  3. Hook click: instanceId → compute that instance's world position → camera bezier toward it → at closest approach, crossfade into the micro scene.
  4. In the micro scene, one hero spore slowly germinates: a germ tube (thin tapered tube geometry) extends out of it — scrub tied to scroll. This is "see how life continues" and foreshadows lesson 07.
  5. Postprocessing pass for the whole app, tuned per episode (bloom subtle in the forest, strong in the micro world; DOF only in micro). An <Effects> component reading the current episode from state.
  6. Back out: a "return" interaction reverses the transition. Both directions must feel intentional.

Exercises

  • Benchmark: 10,000 instanced spores vs 10,000 merged static meshes vs 10,000 individual meshes. Measure draw calls (gl.info.render.calls via useThree). Feel the difference in your bones; this is the whole argument for instancing.
  • Per-instance "aliveness": one random spore occasionally twitches. Selecting which one in the shader without CPU: step/mod tricks on aSeed + uTime.
  • Compare the same scene with and without DOF + bloom. Screenshot both. Write one sentence on what each effect contributes. (Taste is trained deliberately.)

Checkpoint

  • When does InstancedMesh stop helping? (Hint: what's shared, what can't be?)
  • Why do per-instance attributes beat updating matrices every frame for ambient motion?
  • In transition #1, what exactly is rendered during the crossfade frame — how many scenes, how many passes?

Quiz

1. InstancedMesh draws N copies cheaply because:

The saving is draw-call and state-change overhead, not vertex work.

2. Per-instance idle wobble is best done by:

Zero CPU per frame; matrices stay static while the shader animates around them.

3. Clicking a specific spore in an InstancedMesh — you know which one via:

R3F forwards the raycaster's instance hit index.

4. "Microscopic" is sold most strongly by which postprocessing choice?

Thin focus is the optical signature of microscopy; the others are seasoning.

5. Instancing stops being the right tool when:

Instancing shares geometry + material by definition; vary those and you need separate meshes (or merged/batched approaches).
