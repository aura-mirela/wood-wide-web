Click, hover, and the way back

What this lesson records: the interaction we settled after reading the running scene. A click reveals one fungal individual. A hover releases spores from any cap. An up arrow sends the camera home and leaves the reveal in place. Read Reveal one individual for the strand geometry, then use this page for what that lesson does not yet say: the return button, the breath ease, and which spore system to keep.

Goal

After this lesson you should be able to:

  • name the two pieces of state, and say which one the up arrow clears;
  • say what is on screen before the first click, and what that click adds at the same time;
  • say why the polar limits have to stay open while the camera travels home;
  • say why a hover uses the lesson 03 point cloud, and what the recycled spore pool was for.

Where the scene is

App draws one canvas and a click-through story overlay. The overlay’s chapter and action are still placeholders. The canvas is a horizon view of procedural ground, mask-scattered firs, and breathing fly agaric caps. Screen size picks the tier: fewer trees, fewer mushrooms, and no shadows on a phone.

assignFungalIndividuals already groups the caps into individuals and stores each individual’s myceliumStrands and rootIndices. Nothing draws those strands yet. Terrain still concatenates every rootIndices and instances the root scan on all of them. That list is what turned the canvas black: on a medium screen it was 56 copies of a five-chunk scan, about 23 million triangles, and the frame never finished. ScatteredMushrooms can pick a cap, but the hit plane mounts only when onSelect is passed, and Terrain does not pass it.

Two states, and they do not read each other

StateLives inWhat it drives
revealedIdsTerrainResting caps, <Line> strands, root flares. Grows when a cap is clicked. A second click appends the next individual. It does not replace the first.
cameraFocusApp, read by ExperienceThe orbit pose. The clicked cap’s world position, or null for home. The up arrow sets it back to null.

Hover is a third, short-lived value: the mushroom index under the pointer, or nothing. It chooses which cap emits spores. It does not read revealedIds, and a click does not read it. A resting cap releases spores the same way a breathing one does.

1. What one click does

The individual already exists. The click looks the mushroom index up in mushroomIndices and appends that id if it is new. The same click reports the placement upward as cameraFocus. Clicking a cap that is already revealed does not add a second copy. It only moves the camera to that cap.

From the revealed records, derive three lists. Before the first click all three are empty.

  • Resting mushrooms. The union of their mushroomIndices. Their scale multiplier eases to 1, which is the small end of the current pulse (1 to 1.4). Snapping from 1.4 to 1 pops, so ease it. Every other cap keeps the shared pulse: amplitude 0.4, speed 2.5, phase index * 1.73. Do not give a group its own speed. That would label it before the click.
  • Strands. One drei <Line worldUnits> per myceliumStrand, width about 0.045. Sample the ground with getTerrainElevation, lift about 0.07, and add a small stable sideways bend. World position is (x, elevation, -y). One warm color per individual id. Orange and cyan stay reserved for the later exchange.
  • Root flares. That individual’s rootIndices only. ScatteredRootFlares already draws nothing when the list is empty, so the scan stays off the GPU until a reveal. One patch is a few firs. The scan is still about 300,000 vertices times five chunks times that fir count, so a patch that swallowed many trees can still hitch.

Build in this order: empty the root list until a reveal, then the resting scale, then the lines, then the camera. The first step is what keeps the canvas from going black again.

2. The camera, and the up arrow

Both polar limits are 1.51, which is the horizon. A little downward is a smaller polar angle, about 1.25, with the orbit target on the clicked mushroom and the distance shortened to about 9. From 16 units away, a tiny tilt still will not show the strands. Keep the azimuth. The camera slides so it still looks from the same compass direction, centered on the cap.

The return control is an upward arrow, rendered only while cameraFocus is set. The camera tilted down, and this control lifts it back: target [-2, 1, -3.5], polar 1.51, and the original distance. Clearing cameraFocus does not clear revealedIds. The lines, the resting caps, and the flares stay.

It is HTML, a sibling of the canvas, with pointer-events: auto and an accessible name such as “Return to the forest view.” The icon is aria-hidden. .story-overlay is pointer-events: none, so clicks pass through it. The arrow glyph in iconMap.jsx points down. That one means “move closer to the ground.” The return control is the same glyph turned up. A left arrow would read as “previous page.”

Two constraints fight the ease:

  • An inline target={[-2, 1, -3.5]} is a new array every render. Drei applies it when the reference changes, which snaps the target home. Memoize the home target once, and let the rig write controls.target after mount.
  • controls.update() clamps polar angle and distance. If the limits jump back to the horizon at the start of the return, the view snaps. While the pose is moving, open the limits across the span between home and the focused pose. When the angle and the distance have arrived, lock min and max to that pose again.

3. Hover releases the spore cloud you already planned

Any cap can emit, whether or not it has been clicked. The pick on the invisible ground plane is the hover test. An index means that cap is emitting. null, or pointer out, means emitting stops. On a phone there is no hover, so the same tap that reveals an individual can also start one short burst.

The drawing is the cloud from Lesson 03. One THREE.Points object. Each point keeps aSeed and aSize. The vertex shader places it as a function of time: up from the gill ring, then a drift. The fragment shader is a soft disc, additive, depthWrite: false, fading in at birth and out at the end. A life uniform runs that life. The mycelium stays a <Line>. The old point shader moves onto this cloud. raycast stays null so the points never steal the click. toneMapped: false keeps the glow bright against the sunset HDR.

While the pointer is on a mushroom, that cloud’s emitter is that cap, about 0.18 above the placement, and the life uniform runs forward. Leave the cap and stop advancing the life. Spores already in the air finish the fade. A new hover either waits for that burst or replaces it.

A recycled pool, with aOrigin and aBirth written from JavaScript, is a different system. It only exists so a second cap can emit while the first puff is still in the air. One emitter uniform would make those living spores jump. This beat does not need two puffs at once, so it does not need the pool. The up arrow is not part of the spore cloud.

Build steps

  1. In Terrain, keep revealedIds. Pass [] for root flares until a click, then only the revealed individuals’ rootIndices.
  2. Pass onSelect into ScatteredMushrooms. Append the matching individual id and call onCameraFocus with that cap’s world position.
  3. Ease the breath of those mushroom indexes to resting scale 1. Leave every other cap on the shared pulse.
  4. Mount one <Line worldUnits> per revealed myceliumStrand.
  5. Hold cameraFocus in App. Ease the orbit when it is set. Show the up arrow only then, and have the arrow set cameraFocus back to null.
  6. Open the polar and distance limits across the whole ease, including the return, and lock them when the pose arrives. Memoize the home target.
  7. On hover, run the lesson 03 point cloud from that cap. Do not add a second particle system.

Exercises

  1. Click mushroom 2, then the up arrow, then mushroom 4. Write what is revealed after each step, and where the camera is.
  2. Name the two props that would snap the camera home even though the rig is lerping.
  3. Hover a resting cap, then a breathing one. Say what is the same about the spores, and what the click changed that the hover did not.
  4. Say which spore bug the aOrigin pool was meant to prevent, and why this beat can skip it.

Checkpoint

  • What does the up arrow clear, and what does it leave on screen?
  • Why are the root flares absent before the first click?
  • Why must the polar limits stay open during the return, not only during the move down?
  • A hover starts spores. Which file’s design draws them, and what does the hover itself change?

Quiz

1. The up arrow:

The reveal lives in Terrain. The arrow only clears the camera pose held in App.

2. Root flares are instanced:

An empty list draws nothing. That is what keeps the heavy scan off the GPU until a click.

3. During the return to the horizon, the polar limits:

controls.update() clamps. Closing the limits at the start of the return snaps the view instead of easing it.

4. Spores on hover are:

The hover is the trigger. The drawing stays one point cloud: birth, drift, and fade in the shader. The pool was a second system, for two puffs in the air at once.
