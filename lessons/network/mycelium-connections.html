How the mycelium connections are built

What this lesson explains: src/lib/buildMyceliumConnections.js, and the three places MyceliumNetwork calls it. The library decides neighbors, who can still grow, and where the points sit. The component stores the clicks, owns the distance for this screen, and draws the points. The shader that makes those points glow is A mycelium web of glowing points.

Goal

After this lesson you should be able to:

  • name the three exported functions and the one call site for each;
  • state the five-neighbor rule and the outward-growth rule;
  • say why a clicked mushroom leaves the breathing list while a neighbor can stay;
  • trace one edge from a quadratic Bézier into the three Float32Arrays;
  • say what nodeIndices: [] changes.

The library does the math. The component keeps the story.

MyceliumNetwork imports three functions:

import {
  buildMyceliumParticleAttributes,
  buildNeighborStar,
  collectExpandableMushroomIndices,
} from '../lib/buildMyceliumConnections'
  1. buildNeighborStar runs in the click effect. The origin it receives is clickedMushroomIndex. It returns { myceliumStrands, nodeIndices }. The component keeps star.myceliumStrands.
  2. collectExpandableMushroomIndices runs in useMemo after the click lists change. Its array is what onExpandableChange sends to Terrain, and what the mushrooms use for breathing.
  3. buildMyceliumParticleAttributes runs in another useMemo. It turns myceliumStrands into positions, sizes, and phases. Those become the buffer attributes on <points>.

maxDistance is not inside the library. MyceliumNetwork picks it from the breakpoint tier: 3.2, 2.9, 2.7, or 3.5. collectOccupiedNodes is also in the component. It builds the set of mushrooms already in the web: every clicked origin, plus both ends of every edge. That set is an argument to the first two library functions.

1. A star of at most five neighbors

buildNeighborStar(placements, originIndex, maxDistance, occupiedNodes) uses the parameter name originIndex. At the call site that value is clickedMushroomIndex. Inside the function it means "the mushroom this star grows from."

Distance is on the flat map, Math.hypot(a.x - b.x, a.y - b.y). Elevation is ignored. Candidates inside maxDistance are sorted nearest first, then cut to MYCELIUM_MAX_NEIGHBORS, which is 5. Each kept candidate becomes { from, to, length }.

If the origin is already in occupiedNodes, candidates that are also occupied are skipped. The star can only reach mushrooms that are not in the web yet. A brand-new origin is not occupied yet, so it may attach to mushrooms that already have edges. A later click can join an existing patch. A click on a mushroom that is already in the patch grows outward.

The component then appends clickedMushroomIndex to clickedMushroomsIndices even when the star has no edges. It appends star.myceliumStrands only when that array is not empty. A second click on the same index returns early, because clickedMushroomsIndicesRef already contains it. That check lives in the component, not in the library.

2. Who can still breathe

collectExpandableMushroomIndices asks the same question for every mushroom: "if this one were clicked now, would buildNeighborStar find at least one neighbor?" The loop variable is also named originIndex. Here it walks every placement. It is not clickedMushroomIndex.

  • A mushroom already in clickedMushroomsIndices is skipped. That is why a clicked mushroom stops breathing.
  • A mushroom that is occupied but was not clicked — a neighbor at the end of an edge — stays in the list when it can still reach someone outside the web.
  • A mushroom outside the web stays in the list when anyone is within maxDistance, including mushrooms that are already connected.

The function returns a new array. It does not delete from the previous one. useLayoutEffect passes that array to onExpandableChange before the browser paints.

3. Edges become points on a curve

buildMyceliumParticleAttributes fills three arrays and copies them into Float32Arrays. positions holds x, y, z for each point. sizes and phases are one number per point. The shader later reads those as aSize and aPhase.

The function can also drop a large point on chosen nodes (sizes.push(3.1)). MyceliumNetwork passes nodeIndices: []. An empty array is a real value, so the ?? fallback does not run, and those node points are skipped. Omit the argument and every placement gets a bright point, including mushrooms that are not in the web.

For each edge the code works on the ground plane:

  1. nx, ny is a unit perpendicular of the segment: (-dy / length, dx / length).
  2. The Bézier control sits at the midpoint, pushed along that perpendicular. hash01 of the two indices picks the side and the amount. curveAmount is 0.3, so the same pair of mushrooms always bows the same way.
  3. quadraticBezier is three lerps: start to control, control to end, then those results together. Samples stay between t = 0.02 and t = 0.98.
  4. Each sample is jittered along the perpendicular. The spread is wider near the middle.
  5. Height is getElevation(x, y) + 0.06. MyceliumNetwork passes getTerrainElevation, so the points follow the hills. World position is (x, elevation, -y).

hash01 turns a number into a stable value in 0…1 by taking the fractional part of a sine. Bend, jitter, size, and phase all come from it. Nothing extra is stored on the placement.

If the strands would exceed maxParticles (18000), spacing grows from 0.14. The web gets coarser instead of allocating without a cap. With nodeIndices: [], that whole budget is available for the curve samples.

Build steps (from this codebase)

  1. On a new clickedMushroomIndex, call buildNeighborStar with the tier distance and the occupied set. Keep at most five edges.
  2. Store the origin in clickedMushroomsIndices and append the new edges to myceliumStrands.
  3. Recompute expandable indices with the same occupied set and the clicked list. Send that array to Terrain.
  4. Call buildMyceliumParticleAttributes with getTerrainElevation and nodeIndices: [].
  5. Attach positions, sizes, and phases to one <points> object.

Exercises

  1. In MyceliumNetwork, find the three call sites. Write which state array each one reads, and which prop or buffer its result becomes.
  2. Click one mushroom, then click it again. The early return is clickedMushroomsIndicesRef.current.includes(clickedMushroomIndex). That check is not inside buildNeighborStar.
  3. Set MYCELIUM_MAX_NEIGHBORS to 1. Each new click should add at most one strand. Restore 5.
  4. Set curveAmount to 0. The strands should run straight. Restore 0.3.
  5. Remove nodeIndices: [] for one reload. A large point should appear on every mushroom. Put the empty array back.

Quiz

1. buildNeighborStar is called with:

The component owns the click and the distance. The function returns the new edges.

2. A mushroom stops breathing when:

Being the end of an edge marks it occupied. It can still breathe if it can reach a mushroom outside the web.

3. The strand bows sideways because:

curveAmount scales that offset. Zero makes the quadratic a straight line.

4. nodeIndices: [] means:

?? replaces null or undefined only. An empty array is a real "draw none of these."

5. hash01 is used so that:

It is a pure function of its input. Math.random would change the strand on every rebuild.
