Network track · one file, from the GLB to the click

How ScatteredMushrooms works

What this lesson explains: every part of src/3d-components/ScatteredMushrooms.jsx. The file draws the fly agaric copies and turns a pointer event into a mushroom index. It does not choose where the mushrooms stand, and it does not grow the mycelium. Those jobs belong to Terrain and MyceliumNetwork. Mushrooms you can click follows the state after this file reports an index.

Goal

After this lesson you should be able to:

  • name the three props and say which one this file is allowed to call;
  • walk from useGLTF to one InstancedMushroomPart per mesh;
  • read one frame of the matrix loop: position, yaw, scale, part offset, setMatrixAt;
  • separate the three factors in the scale: placement variety, MUSHROOM_BASE_SCALE, and breath;
  • say what the invisible plane knows, and what pickNearestMushroomIndex adds.

1. Two jobs, three props

export default function ScatteredMushrooms({
  expandableMushroomsIndices = [],
  onSelect,
  placements,
})
  • placements is the list from scatterObjectsOnTerrain. Each item is { x, y, elevation, rotationY, scale }. This file only stamps the model onto that list.
  • expandableMushroomsIndices is a list of copy indexes that should breathe. The default [] means every copy stays at rest size. The list does not enable or block clicks.
  • onSelect is optional. When Terrain passes setClickedMushroomIndex, a successful pick calls onSelect(index). With no onSelect, the mushrooms still draw and the hit plane is left out.

If placements.length === 0, the component returns null before any mesh is created.

2. Read the GLB into part records

useGLTF(MUSHROOM_MODEL_URL) loads /models/fly_agaric_mushroom.glb and returns a scene. That scene is a source of meshes. It is not placed in the canvas.

A useMemo walks it once:

scene.updateMatrixWorld(true)
scene.traverse((child) => {
  if (!child.isMesh) return

  meshes.push({
    geometry: child.geometry,
    material: child.material,
    localMatrix: child.matrixWorld.clone(),
  })
})

updateMatrixWorld(true) runs first because this scene is never added to the canvas, so the renderer will not refresh it. matrixWorld is where that part sits inside the file: the cap above the stem, the stem above the origin. localMatrix is a clone of that matrix, so later edits to the loaded scene cannot move the copies. If you skip the update, matrixWorld can still be the identity and every part instances on top of the same point.

useGLTF.preload(MUSHROOM_MODEL_URL) at the bottom of the file starts the download when the module is imported, before the component renders. It does not create meshes.

The code does not name the parts. However many meshes the file contains, that is parts.length.

3. One InstancedMesh per part

{parts.map((part, index) => (
  <InstancedMushroomPart
    key={index}
    geometry={part.geometry}
    material={part.material}
    localMatrix={part.localMatrix}
    placements={placements}
    expandableMushroomsIndices={expandableMushroomsIndices}
  />
))}

index here is the part index, used only as the React key. Every part receives the same placements array. Inside each part, the instanced mesh is:

<instancedMesh
  args={[geometry, material, placements.length]}
  castShadow
  receiveShadow
  raycast={null}
/>

placements.length is how many copies to allocate. The geometry and material are the objects taken from the GLB. They are shared by every copy of that part. castShadow and receiveShadow let the copies take part in the scene shadows. raycast={null} means a click never hits the cap or the stem. Section 6 is what receives the pointer instead.

4. One matrix per copy, every frame

The instanced mesh starts with identity matrices, so every copy would sit at the origin. useFrame rewrites them before each draw. The firs can write once in useLayoutEffect because their scale never changes. These copies breathe, so the matrix has to be written again whenever time changes.

placements.forEach((placement, index) => {
  const breath = expandableSet.has(index)
    ? 1 + BREATH_AMPLITUDE * (0.5 + 0.5 * Math.sin(time * BREATH_SPEED + index * 1.73))
    : 1

  dummy.position.set(placement.x, placement.elevation, -placement.y)
  dummy.rotation.set(0, placement.rotationY, 0)
  dummy.scale.setScalar(placement.scale * MUSHROOM_BASE_SCALE * breath)
  dummy.updateMatrix()
  composed.multiplyMatrices(dummy.matrix, localMatrix)
  mesh.setMatrixAt(index, composed)
})
  • dummy is one scratch Object3D, created once with useMemo. The loop reuses it instead of allocating an object per mushroom per frame.
  • Position is (x, elevation, -y). The ground mesh is rotated -90° on X. These instances are siblings of that mesh, so they do not inherit the rotation. Height becomes world Y. The minus sign keeps the copies on the same side of the plane as the hills.
  • Rotation is yaw only. X and Z stay 0, so the mushroom stays upright.
  • Scale is three factors multiplied. placement.scale is the variety from the scatter, roughly 0.8 to 1.2. MUSHROOM_BASE_SCALE is 0.0025, which brings the large source file down to a mushroom. breath is 1 for a resting copy, or a number from 1 to about 1.24 for a copy whose index is in expandableMushroomsIndices.
  • updateMatrix() bakes position, rotation, and scale into dummy.matrix.
  • composed is another reused Matrix4. multiplyMatrices(dummy.matrix, localMatrix) applies the part offset first, then moves the whole mushroom onto the hill. That is what keeps the cap on the stem of the same copy.
  • setMatrixAt(index, composed) stores it. This index is the copy, not the part. Copy 3 on every part is the same mushroom.

The breath formula, when the index is in the set:

  • BREATH_SPEED is 2.4 radians per second.
  • 0.5 + 0.5 * sin(...) maps the sine from -1…1 into 0…1, so the copy only grows above its rest size.
  • BREATH_AMPLITUDE is 0.24, so the extra scale tops out near 0.24.
  • index * 1.73 shifts the phase. Neighboring copies do not inhale on the same frame.

expandableSet is a Set built from expandableMushroomsIndices, so each copy can ask has(index) without scanning the array. An index missing from the set gets breath 1.

5. Upload the matrices, then measure the bounds once

mesh.instanceMatrix.needsUpdate = true

if (!boundsReadyRef.current) {
  mesh.computeBoundingSphere()
  boundsReadyRef.current = true
}

needsUpdate tells Three.js to upload the matrix buffer to the GPU this frame. Without it, the copies stay at the origin even though setMatrixAt changed the JavaScript arrays.

computeBoundingSphere() builds the sphere used for frustum culling. A fresh instanced mesh still describes one model at the origin. The sphere is computed on the first frame only. Later frames change scale by a small breath, and the copies do not walk to a new patch of ground, so that first sphere still encloses them. boundsReadyRef is a ref so the flag survives re-renders without causing another one.

6. The hit plane and the picker

MushroomHitTargets renders only when onSelect was passed:

<mesh
  rotation={[-Math.PI / 2, 0, 0]}
  position={[0, 0.02, 0]}
  onClick={...}
  onPointerMove={...}
  onPointerOut={...}
>
  <planeGeometry args={[TERRAIN_SIZE, TERRAIN_SIZE]} />
  <meshBasicMaterial transparent opacity={0} depthWrite={false} />
</mesh>

The plane matches the terrain size, lies flat, and sits 0.02 above the ground. Opacity 0 keeps it invisible. depthWrite: false keeps that invisible surface from hiding the soil. This mesh is the event target. It knows that the pointer hit the ground. It does not know which mushroom that was.

selectAtPointer calls event.stopPropagation() so the click does not also drag the orbit controls, then calls pickNearestMushroomIndex with the placements, event.pointer, the camera, the canvas size, and MUSHROOM_PICK_MAX_DISTANCE_PX (40).

Inside pickNearestMushroom.js the search is in pixels:

  1. Convert the pointer from normalized device coordinates to pixels. Screen Y grows downward, so the pointer's Y is flipped.
  2. For each placement, project the world point (x, elevation + 0.18, -y). The extra 0.18 lifts the test into the cap.
  3. Skip a mushroom whose projected z is outside -1…1. It is outside the camera volume.
  4. Keep the index with the smallest squared pixel distance, and only if that distance is within 40².

The function returns null when nothing is close enough. On click, a real index is passed to onSelect. On move, a hit sets document.body.style.cursor to pointer; onPointerOut sets it back to auto.

The picker does not read expandableMushroomsIndices. A resting mushroom can still be selected. What happens to that index after onSelect is Terrain's state and MyceliumNetwork's graph. This file's job ends at the call.

Build steps (from this codebase)

  1. Preload the GLB URL. Load it with useGLTF and keep the returned scene off the canvas.
  2. Force updateMatrixWorld(true), then collect { geometry, material, localMatrix } for every mesh.
  3. Render one instancedMesh per part, with args={[geometry, material, placements.length]}, shadows on, and raycast={null}.
  4. In useFrame, write (x, elevation, -y), yaw, and placement.scale * 0.0025 * breath. Multiply by localMatrix and setMatrixAt.
  5. Set instanceMatrix.needsUpdate every frame. Compute the bounding sphere once.
  6. When onSelect exists, catch the pointer on an invisible ground plane and resolve the copy with pickNearestMushroomIndex.

Exercises

  1. Log parts.length after the useMemo. That number is how many InstancedMushroomPart elements mount, and how many draw calls the mushrooms cost.
  2. Set MUSHROOM_BASE_SCALE to 1 for one reload. The copies should dwarf the terrain. Restore 0.0025.
  3. Remove the minus on placement.y in dummy.position.set. The copies should mirror across X relative to the hills. Put the minus back. The picker uses the same minus; change only the instance line so you can see the models leave the pick points.
  4. Replace mesh.setMatrixAt(index, composed) with mesh.setMatrixAt(index, dummy.matrix) for one reload. The parts of one mushroom should stack on the same origin. Restore composed.
  5. Temporarily pass expandableMushroomsIndices={[]} from Terrain. Every copy should stay still. A click should still call onSelect. Restore the prop.
  6. Comment out <MushroomHitTargets />. The mushrooms should stay visible, and clicks should stop changing clickedMushroomIndex. Put the element back.

Quiz

1. placements arrives from:

This file consumes the list. Scatter, mask, and elevation happen before the prop is passed.

2. parts.map returns:

Each mesh keeps its own geometry, material, and localMatrix. Every part then draws every placement.

3. Copy index 3 on two different parts is:

Both parts walk the same placements array. The key on InstancedMushroomPart is which part, not which mushroom.

4. MUSHROOM_BASE_SCALE is 0.0025 because:

Without the base scale, each copy is enormous. Breath and the scatter scale are extra multipliers on top of it.

5. expandableMushroomsIndices changes:

The set is read in the scale line. The picker still searches every placement within 40 pixels.
