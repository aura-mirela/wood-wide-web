Reveal one individual

What this lesson explains: how a click shows the mycelium that One species, several individuals already stored. The individual exists on load. The click reveals it: its soil lines, its root flares, and a closer view from above. The blocks below are pseudocode for files you have not written yet.

Goal

After this lesson you should be able to:

  • say why the canvas stayed black, and which list caused it;
  • draw <Line> only for a revealed individual’s myceliumStrands;
  • trace a click from the mushroom index to that individual’s id, and a second click that adds the next individual;
  • say where the hand cursor already lives, and why it never shows until onSelect is passed;
  • put the orbit ease in a component that Experience.jsx renders, and say why the polar clamp has to open.

1. The black frame was the root scan

A previous attempt stayed black. The line component was in that attempt, and the undo took the line with it. The frame died because ScatteredRootFlares was mounted for every colonized fir at once. On a medium screen that was 56 copies of the five-chunk scan, about 300,000 vertices each. One frame was trying to draw about 23 million triangles, so the canvas never finished a frame.

The ground, the firs, and the mushrooms in that same view are about 855,000 triangles. ScatteredRootFlares already returns nothing when rootIndices is empty. The caller is what still selects every fir:

rootIndices = individuals.flatMap(individual => individual.rootIndices)
ScatteredRootFlares(placements, rootIndices)

This beat closes that. Pass rootIndices only for individuals whose id is in the revealed list. Before the first click that list is empty, so the scan is not instanced. A click adds the flares for that one individual: a handful of firs, not the forest.

revealedRootIndices(individuals, revealedIds):
  roots = []
  for each individual in individuals:
    if revealedIds contains individual.id:
      append individual.rootIndices
  return roots

A soil line cannot reproduce that triangle count. One strand is a short ribbon. One individual has a handful of strands. The line also does not load fir_trunk._spruce_trunk.glb.

2. Lines for the revealed strands

<Line> from drei draws the points you give it. It has no click of its own. The gate is the list Terrain passes in. Start revealedIds at []. MyceliumLines maps that list, so the first frame mounts zero lines.

A strand end is { kind: 'mushroom' | 'root', index }. A mushroom end reads mushroomPlacements. A root end reads treePlacements, the same fir index the flare uses. Sample about a dozen points along the ground. Placement y is the ground axis; the scene stores it as world z = -y, the same mapping the mushrooms use.

MyceliumLines(revealedIndividuals, mushroomPlacements, treePlacements):
  if revealedIndividuals is empty:
    draw nothing

  for each individual in revealedIndividuals:
    color = a warm color for this id, the first one #ffc56a
    for each strand in individual.myceliumStrands:
      samples = []
      for t from 0 to 1, about a dozen steps:
        x, y = lerp the two ends on the ground plane
        slide x, y sideways by a small bend
          that is 0 at both ends and stable for this strand
        height = getTerrainElevation(x, y) + 0.07
        append [x, height, -y]
      draw Line(
        points = samples,
        color,
        lineWidth = 0.045,
        worldUnits
      )

worldUnits keeps the stroke a hair in the world when the camera comes closer. A pixel width would stay a constant screen stroke. Orange and cyan stay reserved for the later exchange on the bark. Two revealed individuals keep two warm colors so their webs stay distinct. The caps stay one model.

3. The click appends one id

The individual is already in memory. The click looks the mushroom index up in mushroomIndices and appends that id. It does not walk the whole placement list, and it does not build a neighbor star.

on mushroom click(index):
  individual = the individual whose mushroomIndices contain index
  if individual is missing:
    return
  if revealedIds does not include individual.id:
    append individual.id
  focus = mushroomPlacements[index]

Terrain renders:
  MyceliumLines(individuals whose id is in revealedIds)
  ScatteredRootFlares(revealedRootIndices)
  ScatteredMushrooms(onSelect = this click)

Walk the example. Mushrooms 1, 2, and 3 belong to A. Mushrooms 4 and 5 belong to B.

  • Click mushroom 2. Append A. Draw A’s strands and A’s flares. B stays dark.
  • Click mushroom 4 later. Append B. A’s lines stay. B’s lines are added.

The same click stops the breath on that individual’s mushrooms. They hold resting scale. Every other cap keeps the shared pulse (BREATH_AMPLITUDE 0.4, BREATH_SPEED 2.5, phase index * 1.73). A different speed per individual would label the groups before the click.

4. The hand is already written

The instanced caps set raycast to null, so a CSS hover on the mushroom mesh never fires. MushroomHitTargets is an invisible plane over the terrain. On pointer move it calls pickNearestMushroomIndex with a 40px radius. Inside that radius the cursor is pointer. Outside it, and on pointer out, the cursor is auto. Click and tap use that same plane’s onClick.

MushroomHitTargets mounts only when onSelect is passed

on pointer move:
  index = pickNearestMushroomIndex(placements, pointer, camera, 40px)
  cursor = pointer when index is a mushroom
  cursor = auto otherwise

on click or tap:
  the same pick
  if index is a mushroom:
    onSelect(index)

Passing onSelect from Terrain is what mounts the plane. Until then the pick, the click, and the hand are all absent.

5. The camera component lives in Experience

Lines on the soil are edge-on from the horizon lock. The click eases the orbit target onto the clicked mushroom, shortens the distance, and lowers the polar angle so the patch is seen from above.

That behavior is a component, ForestOrbit, rendered by Experience.jsx. Experience already owns the canvas, the tier, and the horizon lock. scatterObjectsOnTerrain stays the function that returns placements. It runs once, outside the canvas, and never sees the camera.

A plain function can name the destination. It cannot ease the camera. The ease needs useFrame and the controls object, which exist only inside the canvas. ForestOrbit holds both the <OrbitControls> limits and that frame loop. Terrain reports the clicked placement upward. Experience stores it as focus and passes it in.

Experience:
  focus = null
  ForestOrbit(tier, focus)
  Terrain(onFocus = (placement) => focus = placement)

ForestOrbit(tier, focus):
  OrbitControls
    while focus is null:
      minPolarAngle = maxPolarAngle = 1.51
      minDistance, maxDistance = the tier (12–16)
      target starts at [-2, 1, -3.5]
    once focus is set:
      minPolarAngle about 0.9
      maxPolarAngle stays 1.51
      minDistance about 5
      maxDistance stays the tier max

  each frame, once focus is set:
    ease controls.target to (focus.x, focus.elevation, -focus.y)
    ease polar angle down, toward about 1.05
    ease distance in, toward about 7
    keep the current side of the patch
    controls.update()

Both polar limits are 1.51 today, and distance cannot go under 12. If those props stay locked, the rig moves the camera and the next controls update pulls it back to the horizon. The limits have to open on the same component that eases. After the ease starts, do not pass a fresh target={[-2, 1, -3.5]} on every render. That pins the orbit center to the old view. The angles and the radius above are starting points. The requirement is a shorter distance and a lower polar angle. Leave the azimuth window as it is.

Build steps

  1. In Terrain, keep revealedIds and replace the flat list of every rootIndices with the revealed firs only. Before a click, pass [].
  2. Pass onSelect into ScatteredMushrooms. On that index, append the matching individual id and report the placement as focus.
  3. Add MyceliumLines and mount it with the revealed individuals only. One <Line worldUnits> per myceliumStrand.
  4. Stop the breath on the mushrooms whose indexes belong to a revealed individual. Leave every other cap on the shared pulse.
  5. Add ForestOrbit. Import it in Experience.jsx in place of the inline <OrbitControls>. Open the polar and distance limits when focus is set, and ease the target onto the clicked mushroom.
