Picking the nearest mushroom

What this lesson explains: src/lib/pickNearestMushroom.js. The invisible plane in MushroomHitTargets only receives the pointer. This function turns that event into a placement index. The strands that grow from the index are the next lesson, A mycelium web of glowing points.

Goal

After this lesson you should be able to:

  • say what the function returns, and when it returns null;
  • separate the invisible plane from the mushroom test point;
  • explain why project(camera) needs the camera;
  • convert an NDC coordinate to a canvas pixel;
  • say why the distance comparison uses squares.

Select the nearest instance

pickNearestMushroomIndex does not raycast the hood, the stem, or the annulus. It walks the placement list and keeps the copy whose test point is closest to the cursor, within 40 canvas pixels. Four steps, as they happen in this file:

  1. Build the world-space position from the placement. The function does not read it off the instancedMesh. mushroomPoint.set(placement.x, placement.elevation + 0.18, -placement.y) is the same ground point as the instance, lifted into the cap.
  2. Project it with .project(camera). mushroomPoint.project(camera) projects that point. In Three.js the result is normalized device coordinates, about -1…1. That is NDC. Before this call, mushroomPoint is still the world position.
  3. Convert those NDC coordinates to canvas pixels. mushroomCanvasPixelX and mushroomCanvasPixelY use (ndc * 0.5 + 0.5) * size. Y is flipped because canvas Y grows downward. The pointer is converted with the same formula, from pointerNdc.
  4. Compare those pixels with the mouse position on the canvas. pixelOffsetX and pixelOffsetY are the gap between the mushroom pixels and pointerX / pointerY. Those pointer values come from pointerNdc, not from clientX and clientY. The smallest squared gap that is still within 40 * 40 wins.

1. The plane is the event target

The instanced mushrooms set raycast={null}, so a click never hits the hood, the stem, or the annulus. The plane is the size of the terrain, lies flat, and sits 0.02 above the ground. It answers "the pointer is over the ground." It does not know which mushroom that was.

This function does not read the point where the ray hit the plane. It compares the cursor with each mushroom.

2. One world point per mushroom

mushroomPoint.set(
  placement.x,
  placement.elevation + heightOffset,
  -placement.y,
)

heightOffset is 0.18. The instances stand at (x, elevation, -y). This test uses that same ground mapping and lifts the point into the cap. The plane's 0.02 and this 0.18 are different heights.

3. The camera turns that point into a screen position

mushroomPoint.project(camera)

project(camera) applies the camera's position, aim, and lens. Orbit or zoom and the same mushroom lands on a different pixel. After this call, mushroomPoint is in normalized device coordinates: x and y about -1…1 across the view, and z is depth. Before the call, the same variable still holds the world position from set.

A z outside -1…1 means the mushroom is outside the camera volume. The loop skips it.

pointerNdc is already in that -1…1 space. The pointer and the mushroom are converted to canvas pixels with the same formula. Screen Y grows downward, so Y is flipped:

const pointerX = (pointerNdc.x * 0.5 + 0.5) * width
const pointerY = (-pointerNdc.y * 0.5 + 0.5) * height

const mushroomCanvasPixelX = (mushroomPoint.x * 0.5 + 0.5) * width
const mushroomCanvasPixelY = (-mushroomPoint.y * 0.5 + 0.5) * height

width and height are the canvas size from useThree(). These pixels start at the canvas corner. clientX and clientY start at the browser window's corner. They match when the canvas fills the window and begins at that corner.

4. Squared pixel distance

const pixelOffsetX = mushroomCanvasPixelX - pointerX
const pixelOffsetY = mushroomCanvasPixelY - pointerY
const squaredPixelDistance = pixelOffsetX * pixelOffsetX + pixelOffsetY * pixelOffsetY

The straight-line gap in pixels would be Math.sqrt(squaredPixelDistance). A gap of 30 pixels is closer than a gap of 50, and 900 is still less than 2500, so the square root would not change which mushroom wins. The loop skips it.

closestSquaredPixelDistance starts at 40 * 40, which is 1600. A candidate replaces it only when its squared distance is smaller. Comparing squaredPixelDistance with 40 would mix pixels squared and pixels. 6.3 * 6.3 is about 40, so that mistake would accept only a gap of about 6 pixels.

The function returns the winning index, or null when every mushroom was outside the camera or farther than 40 pixels.

Build steps (from this codebase)

  1. Convert pointerNdc to canvas pixels. Flip Y.
  2. For each placement, write (x, elevation + 0.18, -y) and project(camera).
  3. Skip NDC z outside -1…1.
  4. Convert the mushroom to canvas pixels with the same formula as the pointer.
  5. Keep the index with the smallest squared pixel distance inside 40 * 40.

Quiz

1. The invisible plane:

The mushrooms set raycast={null}. The plane is the event target. The picker never reads the ray's hit point on the plane.

2. mushroomPoint.project(camera):

Position, aim, and lens all change the pixel. Orbiting moves the mushroom on the canvas without moving its placement.

3. pointerNdc and mushroomPoint after project are:

The shared formula (x * 0.5 + 0.5) * width is what puts them in one pixel space. Y is flipped because screen Y grows downward.

4. closestSquaredPixelDistance starts at 40 * 40 because:

Squaring preserves which gap is smaller, so Math.sqrt is unnecessary. The limit has to use the same units.

5. The function returns null when:

Breathing and the web come later. This function only searches placements against the cursor.
