Network track · lifted state, screen-space picking, a breathing instance

Mushrooms you can click

What this lesson explains: how a click on the forest becomes a mushroom index, and how mushrooms that can still grow the web breathe. The GLB split and the first matrix write live in Instancing scattered firs and mushrooms. This lesson starts after that.

Goal

After this lesson you should be able to:

  • name which component owns clickedMushroomIndex and expandableMushroomsIndices, and which components only receive them;
  • walk one click from the invisible plane to setClickedMushroomIndex;
  • explain screen-space picking: project a world point, measure pixels, keep the nearest inside a radius;
  • say why the instanced mushrooms do not raycast;
  • read the breath formula and say what index * 1.73 is for.

1. Terrain holds the conversation

Terrain is the parent of both the mushrooms and the mycelium. It keeps two pieces of interaction state:

const [clickedMushroomIndex, setClickedMushroomIndex] = useState(null)
const [expandableMushroomsIndices, setExpandableMushroomsIndices] = useState([])
  • clickedMushroomIndex is the mushroom that was just clicked. null means nothing has been chosen yet.
  • expandableMushroomsIndices is the list of mushrooms that can still extend the web. The network computes it. The mushrooms only display it.

The props make a loop through the parent:

<ScatteredMushrooms
  placements={mushroomPlacements}
  expandableMushroomsIndices={expandableMushroomsIndices}
  onSelect={setClickedMushroomIndex}
/>
<MyceliumNetwork
  placements={mushroomPlacements}
  clickedMushroomIndex={clickedMushroomIndex}
  onExpandableChange={setExpandableMushroomsIndices}
/>

A click calls onSelect(index), which is setClickedMushroomIndex. The network sees the new index, grows edges, then calls onExpandableChange with the mushrooms that are still worth clicking. Those indices come back down as expandableMushroomsIndices. Neither child stores the other's result.

2. The same world position, every frame

A placement is still { x, y, elevation, rotationY, scale }. The ground mesh is rotated -90° on X, and the mushrooms are siblings of that mesh, so they do not inherit the rotation. World position is:

dummy.position.set(placement.x, placement.elevation, -placement.y)

The firs write that matrix once, in useLayoutEffect. The mushrooms write it inside useFrame, because the scale changes every frame. instanceMatrix.needsUpdate = true uploads the new matrices. computeBoundingSphere() runs only on the first frame (boundsReadyRef). The copies move by scale, not by leaving the patch of ground, so the sphere from the first frame still encloses them.

MUSHROOM_BASE_SCALE is 0.0025. placement.scale is only the size variety from the scatter. The base scale is what brings the Sketchfab file down to a mushroom.

3. Breathing is the affordance

Before the loop, the expandable indices become a Set so each copy can ask "am I in the list?" without scanning the array.

const breath = expandableSet.has(index)
  ? 1 + BREATH_AMPLITUDE * (0.5 + 0.5 * Math.sin(time * BREATH_SPEED + index * 1.73))
  : 1

dummy.scale.setScalar(placement.scale * MUSHROOM_BASE_SCALE * breath)
  • BREATH_AMPLITUDE is 0.24. The scale swings from 1 to about 1.24.
  • 0.5 + 0.5 * sin(...) maps the sine from -1…1 into 0…1, so the mushroom only grows above its rest size.
  • BREATH_SPEED is 2.4 radians per second.
  • index * 1.73 is a phase shift. Neighboring mushrooms do not inhale on the same frame. 1.73 is just a number that is not a tidy fraction of the circle.

A mushroom that is not expandable stays at breath 1. Stillness means "this one has already been used, or it has nobody left to connect to."

4. The meshes do not take the click

Each <instancedMesh> sets raycast={null}. Three.js will not test the cap, the stem, or the annulus. An invisible plane does:

<mesh
  rotation={[-Math.PI / 2, 0, 0]}
  position={[0, 0.02, 0]}
  onClick={...}
  onPointerMove={...}
>
  <planeGeometry args={[TERRAIN_SIZE, TERRAIN_SIZE]} />
  <meshBasicMaterial transparent opacity={0} depthWrite={false} />
</mesh>

The plane is the size of the terrain, turned flat, and lifted 0.02 so it sits just above the ground. Opacity 0 keeps it invisible. depthWrite: false keeps that invisible surface from hiding the soil. stopPropagation() on the event keeps the click from also moving the orbit controls.

The plane only answers "the pointer hit the ground here." It does not know which mushroom that was. selectAtPointer does.

5. Pick the nearest mushroom in pixels

pickNearestMushroomIndex receives the placement list, event.pointer (normalized device coordinates, about -1…1), the camera, the canvas size in pixels, and MUSHROOM_PICK_MAX_DISTANCE_PX (40).

  1. Turn the pointer into pixels. NDC x maps to 0…width. NDC y is flipped, because screen Y grows downward.
  2. For each placement, build the same world point the instance uses, plus 0.18 on Y so the test sits in the cap rather than in the soil: (x, elevation + 0.18, -y).
  3. mushroomPoint.project(camera) puts that point into clip space. If z is outside -1…1, the mushroom is behind the camera or beyond the far plane. Skip it.
  4. Convert the projected x and y to pixels with the same mapping as the pointer.
  5. Keep the index with the smallest squared pixel distance, but only if that distance is inside 40². Squared distance avoids a square root. The comparison is the same.

If nothing is close enough, the function returns null and the click does nothing. On move, a hit sets document.body.style.cursor to pointer; leaving the plane sets it back to auto.

This is a screen-space test, not a ray against each triangle. A mushroom far away occupies fewer pixels, so the same 40-pixel radius is stricter in the world. That is what you want for a click: "is the cursor near this mushroom on the screen?"

Build steps (from this codebase)

  1. Keep clickedMushroomIndex and expandableMushroomsIndices on Terrain. Pass setters down as onSelect and onExpandableChange.
  2. Draw mushrooms as instanced parts. Update matrices in useFrame when scale must change over time.
  3. Scale expandable copies with a sine that never goes below 1, and offset the phase by the copy index.
  4. Turn raycasting off on the instances. Catch the pointer with a flat, invisible plane the size of the terrain.
  5. Project each mushroom to pixels and keep the nearest one inside a pixel radius.

Exercises

  1. On paper, start from a click on the plane and name every function until clickedMushroomIndex changes. Include selectAtPointer, pickNearestMushroomIndex, and onSelect.
  2. Set MUSHROOM_PICK_MAX_DISTANCE_PX to 8. Click near a cap, but not on the point the picker tests. The click should miss. Restore 40.
  3. Remove + index * 1.73 from the sine. Expandable mushrooms should inhale together. Put the offset back.
  4. Temporarily pass expandableMushroomsIndices={[]} from Terrain. Nothing should breathe. Clicks should still set clickedMushroomIndex. Restore the real prop.
  5. Take the placement { x: 2, y: 4, elevation: 0.2 } and write the world position used by the instance, then the world position used by the picker.

Quiz

1. clickedMushroomIndex is stored in:

The parent owns the click. The mushrooms report an index. The network consumes it.

2. Expandable mushrooms change size by:

The geometry stays shared. Only that copy's matrix scale changes. needsUpdate uploads the buffer.

3. index * 1.73 inside the sine:

Same speed, different starting point on the wave. Remove it and every expandable cap moves together.

4. The click lands on the invisible plane because:

The plane reports a ground hit. pickNearestMushroomIndex then chooses a mushroom in pixels.

5. A mushroom is ignored by the picker when:

Clip z throws out mushrooms outside the camera volume. The pixel radius throws out clicks that only landed on empty ground.
