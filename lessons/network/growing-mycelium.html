Network track · a growing graph, Bézier particles, a point-sprite shader

A mycelium web of glowing points

What this lesson explains: what happens after clickedMushroomIndex changes. MyceliumNetwork grows a small star of links, turns those links into points along curves, and draws the points with a custom shader. Read Mushrooms you can click first.

Goal

After this lesson you should be able to:

  • describe the web as nodes and edges, and state the five-neighbor rule;
  • say why the click effect reads refs and writes them before setState;
  • trace one edge from a quadratic Bézier to a Float32Array;
  • read the vertex shader's size, twinkle, and distance term;
  • say what additive blending and depthWrite: false do to overlapping spores.

1. A graph that only grows outward

Each mushroom index is a node. Each link is an edge { from, to, length }. clickedMushroomsIndices is the list of mushrooms the player has chosen. myceliumStrands is every edge added so far.

collectOccupiedNodes puts both lists into one Set: every clicked origin, and both ends of every edge. A mushroom that was only a neighbor is occupied even though the player never clicked it.

buildNeighborStar runs for the new origin:

  1. Skip mushrooms beyond maxDistance. That radius comes from the breakpoint tier: 3.2, 2.9, 2.7, or 3.5.
  2. Sort the rest nearest-first.
  3. Keep at most MYCELIUM_MAX_NEIGHBORS (5).

If the origin is already occupied, candidates that are also occupied are skipped. The star can only reach mushrooms that are not in the web yet. A brand-new origin is not occupied, so it may attach to mushrooms that already have edges. That is how a later click can join an existing patch, while a click inside the patch keeps growing outward.

collectExpandableMushroomIndices uses the same rule in reverse. A mushroom is expandable when it has not been clicked and it still has at least one legal neighbor. useLayoutEffect sends that list to Terrain before the browser paints, so the breathing scale can update in the same commit as the new strands.

2. Refs so one click stays one click

The growth effect depends on clickedMushroomIndex, placements, and maxDistance. It must also read the edges it has already stored. If those arrays were in the dependency list, appending an edge would run the effect again.

Two refs mirror the state. The effect reads clickedMushroomsIndicesRef.current. If this origin is already in that list, it returns. Otherwise it computes the star, writes the next arrays into the refs immediately, then calls setClickedMushroomsIndices and setMyceliumStrands. The ref update is synchronous, so a second run in the same turn still sees the origin as clicked. The setState is what makes React rebuild the buffers.

3. Edges become points on a curve

buildMyceliumParticleAttributes fills three arrays: positions (xyz), sizes, and phases. They are copied into Float32Arrays and attached as buffer attributes. One <points> draws every spore.

The function can also drop a large point on chosen nodes (sizes.push(3.1)). MyceliumNetwork passes nodeIndices: []. An empty array is a real value, so the ?? fallback does not run, and those node points are skipped. Omit the argument and every placement gets a bright point, including mushrooms that are not in the web.

For each edge:

  1. Measure the segment on the ground plane. nx, ny is a unit perpendicular: (-dy / length, dx / length).
  2. Place the Bézier control at the midpoint, pushed along that perpendicular by bend. bend is a hash of the two indices, in about ±0.15 * length because curveAmount is 0.3. The same pair of mushrooms always bows the same way.
  3. Sample t from just after 0 to just before 1. quadraticBezier is three lerps: origin to control, control to end, then those two results together.
  4. Jitter each sample along the perpendicular. spread is wider near the middle of the strand.
  5. Set height from getTerrainElevation(x, y) + 0.06, then store world (x, elevation, -y). The points follow the hills and sit just above the soil.

hash01 turns an integer-ish key into a stable value in 0…1 (sin, then the fractional part). Bend, jitter, size, and twinkle phase all come from it. Nothing extra is stored on the placement.

If the strands would exceed maxParticles (18000), spacing is scaled up. The web gets coarser instead of allocating without a cap. With nodeIndices: [], the whole budget is available for edge samples.

4. The material is a point sprite

vite-plugin-glsl imports each .glsl file as a string. ShaderMaterial is created once in useMemo. A cleanup effect calls material.dispose().

Uniforms are also created once. useFrame writes uniforms.uTime.value = state.clock.elapsedTime. That mutates the object the GPU already reads. It does not call setState, so React does not re-render every frame.

The vertex shader runs per point:

  • aSize and aPhase are the attributes from the buffers.
  • twinkle is 0.2 + 0.18 * sin(uTime * 1.7 + aPhase * 2π). Each point pulses on its own phase.
  • mvPosition.z is view-space depth, negative in front of the camera. attenuation = 190 / max(1, -mvPosition.z) makes nearer points larger in pixels, the way a world-sized object would be.
  • gl_PointSize is aSize * twinkle * attenuation, in pixels. gl_Position is the usual projection.

The fragment shader runs per pixel of that square. gl_PointCoord is 0…1 across the point. Subtract 0.5 and take the length to get distance from the center. Two Gaussians share that distance: exp(-dist² * 14) is the wide halo, exp(-dist² * 55) is the tight core. Both multiply uColor (#ffc56a). Alpha stays 1. The falloff is in the color brightness, which matters once blending is additive.

5. How the points sit in the scene

  • AdditiveBlending adds a spore's color onto whatever is already there. Overlaps get brighter. They do not cover each other with a square.
  • transparent: true is what allows that blending. depthWrite: false keeps the points from writing the depth buffer, so a near spore does not punch a hole in the ground or in another spore.
  • toneMapped: false leaves the glow outside the renderer's tone mapping, so it stays hot against the night scene.
  • frustumCulled={false} draws the cloud even when the geometry bounds are stale or tight.
  • raycast={null} keeps the points from taking clicks that belong to the mushroom plane.

The component returns null when there are no placements or no positions. The first frame, before any click, myceliumStrands is empty, so there is nothing to draw.

Build steps (from this codebase)

  1. On each new clickedMushroomIndex, grow a star of at most five neighbors inside the tier radius. Remember occupied nodes so later clicks grow outward.
  2. Mirror the edge list in a ref, update the ref before setState, and keep the arrays out of the effect's dependency list.
  3. Publish expandable indices in useLayoutEffect.
  4. Sample each edge along a quadratic Bézier, bend and jitter with hash01, and sit the samples on getTerrainElevation.
  5. Draw one <points> object. Size the points in the vertex shader. Shape them in the fragment shader. Blend additively and skip depth writes.

Exercises

  1. Click one mushroom, then click it again. Write down which check returns early, and which ref makes that check see the first click.
  2. Set MYCELIUM_MAX_NEIGHBORS to 1. Each new click should add at most one strand. Restore 5.
  3. Set curveAmount to 0. The strands should run straight between mushrooms. Restore 0.3.
  4. Remove nodeIndices: [] from the buildMyceliumParticleAttributes call for one reload. A large point should appear on every mushroom, not only on the web. Put the empty array back.
  5. In the vertex shader, set attenuation to 1.0. Dolly in. The spores should keep a fixed pixel size. Restore 190.0 / max(1.0, -mvPosition.z).
  6. Switch blending to NormalBlending and set depthWrite to true. You should see hard squares. Restore additive blending and depthWrite: false.

Quiz

1. One click adds at most five edges because:

Everyone inside the tier radius is a candidate. Only the nearest five become edges.

2. The growth effect updates a ref before setState so that:

State updates are asynchronous. The ref is the copy the effect trusts on the next enter.

3. The strand bows sideways because the control point:

curveAmount scales that offset. Zero makes the quadratic into a straight line.

4. gl_PointSize gets larger when the point is closer because:

Point size is in pixels. Dividing by depth is what makes a near spore cover more of the screen.

5. Overlapping spores brighten instead of drawing solid squares because:

The raster square is still a square. The Gaussian and additive blend are what the eye reads as a glow.
