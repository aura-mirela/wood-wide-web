TypeScript specifics for custom R3F materials

The problem this lesson solves: the browser can know that a custom material exists while TypeScript still reports that testShaderMaterial is missing from JSX.IntrinsicElements. Runtime registration and type registration are separate jobs.

Goal

Create a custom shader material that:

  • loads vertex and fragment GLSL files;
  • is registered with React Three Fiber at runtime;
  • is recognized by TypeScript as <testShaderMaterial />;
  • is imported for its side effect without an unused import;
  • is attached to a mesh as a material rather than rendered as a React component.

1. Pick the correct file extension

ExtensionUse it when
.tsThe file contains TypeScript but no JSX. A custom-material definition normally belongs here.
.tsxThe file contains TypeScript and JSX such as <mesh>.
.js / .jsxJavaScript files. TypeScript cannot infer your custom R3F element as precisely without extra declarations.

Your material definition contains no JSX, so prefer:

src/materials/TestShaderMaterial.ts

Using .tsx still compiles, but it suggests JSX is present when it is not. File extensions communicate intent to both tools and readers.

2. Understand what shaderMaterial() returns

const TestShaderMaterial = shaderMaterial(
  {
    uTime: 0,
    uColor: new Color('#00ffcc'),
  },
  vertexShader,
  fragmentShader,
)

shaderMaterial() returns a constructor: a class derived from THREE.ShaderMaterial. It is not a React component and it is not yet an instantiated material.

This distinction explains why this is wrong:

<TestShaderMaterial /> // React interprets uppercase names as components

It also explains why this is incomplete:

<primitive object={TestShaderMaterial} /> // object receives the constructor, not an instance

3. Runtime registration with extend

extend({ TestShaderMaterial })

extend adds the constructor to R3F's runtime catalogue. R3F transforms the PascalCase constructor name into a lower-camel-case JSX tag:

TestShaderMaterial  →  <testShaderMaterial />

The lowercase first letter matters:

  • <TestShaderMaterial /> asks React to call a component.
  • <testShaderMaterial /> asks R3F to construct an item from its catalogue.

4. Type registration with module augmentation

extend runs in the browser, but TypeScript checks your source before the browser runs it. You must describe the new catalogue entry:

import { extend, type ThreeElement } from '@react-three/fiber'

declare module '@react-three/fiber' {
  interface ThreeElements {
    testShaderMaterial: ThreeElement<typeof TestShaderMaterial>
  }
}

This is called module augmentation: you are adding one property to R3F's existing ThreeElements interface.

  • testShaderMaterial must exactly match the lowercase JSX tag.
  • typeof TestShaderMaterial means “the type of this constructor,” not an instance type.
  • ThreeElement<...> converts the Three.js constructor into valid R3F JSX props.
  • import type marks ThreeElement as compile-time-only; it adds no browser JavaScript.

5. The complete material module

import { shaderMaterial } from '@react-three/drei'
import { extend, type ThreeElement } from '@react-three/fiber'
import { Color } from 'three'

import vertexShader from '../shaders/vertex.glsl'
import fragmentShader from '../shaders/fragment.glsl'

const TestShaderMaterial = shaderMaterial(
  {
    uTime: 0,
    uColor: new Color('#00ffcc'),
  },
  vertexShader,
  fragmentShader,
)

extend({ TestShaderMaterial })

declare module '@react-three/fiber' {
  interface ThreeElements {
    testShaderMaterial: ThreeElement<typeof TestShaderMaterial>
  }
}

export default TestShaderMaterial

6. Imports and exports: three different intentions

Default import

import TestShaderMaterial from './materials/TestShaderMaterial'

Use this when the current file directly needs the exported constructor—for example, to instantiate it with new TestShaderMaterial(). A module can have only one default export, and the importing file may choose any local name.

Named import

export { TestShaderMaterial }
import { TestShaderMaterial } from './materials/TestShaderMaterial'

Use named exports when a module exports several related values. The imported name must match unless you alias it with as.

Side-effect import

import './materials/TestShaderMaterial'

This means: “run this module, but do not bind one of its exports to a local variable.” It is appropriate here because importing executes extend({ TestShaderMaterial }). After that registration, JSX can use the lowercase catalogue element:

<Sphere args={[1, 32, 32]}>
  <testShaderMaterial />
</Sphere>

Prefer extensionless application imports. Write ./materials/TestShaderMaterial, not ./materials/TestShaderMaterial.tsx; Vite and TypeScript resolve the source extension.

7. Attachment and scene-tree placement

A material belongs inside the mesh whose material property it should replace:

<Sphere args={[1, 32, 32]}>
  <testShaderMaterial />
</Sphere>

R3F recognizes material objects and automatically attaches this one to the parent's material property. You can be explicit:

<testShaderMaterial attach="material" />

A self-closing parent cannot have children:

<Sphere />                 // already closed
<testShaderMaterial />     // sibling, not the sphere's material
</Sphere>                  // unmatched closing tag

8. Uniform props and refs

The defaults passed to shaderMaterial() become uniform-backed properties, so you can provide initial values as JSX props:

<testShaderMaterial
  uTime={0}
  uColor={new Color('#ff8844')}
/>

For per-frame animation, hold a ref and update the material property rather than React state:

const material = useRef<InstanceType<typeof TestShaderMaterial>>(null)

useFrame(({ clock }) => {
  if (material.current) {
    material.current.uTime = clock.elapsedTime
  }
})

return <testShaderMaterial ref={material} />

This case directly uses the constructor in the component's type, so use a normal import rather than only a side-effect import.

Common errors and what they mean

ErrorLikely cause
testShaderMaterial does not exist on JSX.IntrinsicElementsMissing or misspelled ThreeElements module augmentation.
TestShaderMaterial is not defined at runtimeThe material module was not imported, so extend never executed.
React component/constructor error from <TestShaderMaterial />Uppercase JSX asked React to treat the material constructor as a component.
The sphere uses the default materialThe custom material is outside the sphere, or it lacks attach="material" in an ambiguous position.
Failed to resolve import "./shaders/..."Relative paths start from the importing file; from materials/, sibling shaders/ is ../shaders/.
Shader compiles but UVs are zeroThe vertex shader assignment is reversed; use vUv = uv.

Quiz

1. What does shaderMaterial() return?

It returns a class/constructor. R3F can instantiate it after catalogue registration, or you can instantiate it with new.

2. What does extend({ TestShaderMaterial }) do?

Runtime registration and TypeScript registration are separate. extend handles runtime only.

3. Which JSX tag maps to the registered TestShaderMaterial constructor?

R3F maps PascalCase constructors to lower-camel-case catalogue elements.

4. Why use import './materials/TestShaderMaterial'?

The import exists for its side effect: executing extend(...).

5. Which file extension best fits a typed material definition containing no JSX?

.ts communicates TypeScript without JSX. R3F does not require .tsx unless the file actually contains JSX.
