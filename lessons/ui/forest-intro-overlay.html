UI track · storyboard-2.png, StoryChapter, Action, the same widths as src/breakpoints/

The forest title and the cursor hint

What this lesson explains: the words come from public/inspiration/storyboard-2.png. Almost every panel has the same two blocks. A heading and a paragraph sit in the top-left. A round icon and one sentence sit along the bottom-left. Those are StoryChapter and Action. The cards, lists, and diagrams on the board are neither. This lesson is the copy, the two components, and how their size and padding change at the same widths the scene already uses. The first chapter you render is panel 1.

Goal

After this lesson you should be able to:

  • take the heading and paragraph from a storyboard-2 panel and say whether the bottom row is a separate gesture;
  • store that copy in one config, with an icon name and an optional action;
  • render StoryChapter and Action beside the canvas, so a drag still orbits the forest;
  • change padding, type size, and line length at 575, 767, and 991 pixels, matching breakpoints.js.

1. Two blocks, and the parts that are not those blocks

StoryChapter is the top block: a heading and one paragraph. It names the moment. Action is the bottom block: a round icon and one sentence. It names the gesture. The icon sits to the left of the sentence, on the same row. “Below” on the board means along the lower edge of the panel, not under the icon.

The number in the cell — “1”, “2”, “7” — is the storyboard’s step index. It is not part of the heading.

These are not an Action, and they are not a StoryChapter:

  • the Fly Agaric classification card on panel 2;
  • the mycelium list on panel 5;
  • the spore size card on panel 7;
  • the cycle diagram on panel 10;
  • the closing “Science lives in the details” cell.

Leave those for their own components later. Forcing them into Action turns that component into a switch of special cases.

2. The words, and where the bottom row is dropped

StoryChapter names the moment. Action is the only line that tells you the gesture, and only when the paragraph does not already tell you. Panel 1 is the chapter you build first:

  • Title: Enter the forest
  • Paragraph: The forest is alive — and so is the fungi beneath your feet. Look around.
  • Action: Move your cursor or swipe to look around.

Use that action sentence at every width. It already names both the mouse and the swipe.

3. One config, two components

storyText.js holds the words and an icon name. It does not hold SVG markup, and it does not hold the rem sizes from the table below. An icon map, a separate small module, turns the name cursor into the SVG. action is optional. Action renders only when that field is present.

export const chapters = [
  {
    id: 'enter-the-forest',
    title: 'Enter the forest',
    body: 'The forest is alive — and so is the fungi beneath your feet. Look around.',
    action: {
      icon: 'cursor',
      label: 'Move your cursor or swipe to look around.',
    },
  },
]

StoryChapter receives title and body. Action receives icon and label. Which chapter is visible comes from the episode. It does not come from getSceneTier. Breakpoints only change the paint.

4. DOM over the canvas, not text in the scene

App currently returns only <Experience />, and Experience returns only <Canvas>. A <Text> or <Html> inside the canvas is attached to a 3D point. Orbiting the camera would slide the title across the forest. This copy is pinned to the screen.

Render the overlay next to the canvas:

<Experience />
<StoryOverlay chapter={chapters[0]} />

StoryOverlay renders StoryChapter and, when chapter.action exists, Action. The sentence already says what to do, so the icon’s alt is empty when the icon is an <img>. An inline SVG needs no alt.

The overlay covers the viewport and does not take the pointer:

position: fixed;
inset: 0;
pointer-events: none;

pointer-events: none is what keeps a drag on the title from eating the orbit. The canvas underneath still receives the swipe. App.css already sets touch-action: none on the canvas.

5. One corner for the chapter, the opposite edge for the action

Inside the fixed overlay, StoryChapter is in normal flow at the start. Action is taken out of that flow and pinned to the bottom-left:

.story-action {
  position: absolute;
  left: 0;
  bottom: 0;
  display: flex;
  align-items: center;
  gap: 0.75rem;
}

align-items: center keeps the round icon on the same line as the sentence. On a narrow screen the sentence wraps to two lines and the icon stays centered on that block. It does not jump above the words.

Give the chapter a max-width so a wide monitor does not stretch the paragraph into a banner. The storyboard keeps it a short column in the corner. The action stays short enough to sit on one line from sm upward.

6. The same widths as the scene

breakpoints.js cuts at 575, 767, 991, and 992. The overlay is paint, so it belongs in CSS, not in getSceneTier and not in storyText.js. Copy those cuts into media queries. If the CSS uses a different number, the type will jump at a different width than the terrain.

xs, max 575sm, 576–767md, 768–991lg and up, min 992
padding1rem1.25rem1.5rem2rem
title1.35rem1.5rem1.75rem2rem
paragraph0.9rem0.95rem1rem1.05rem
title block max-widthnone36rem28rem26rem
icon2rem2.25rem2.5rem2.75rem

On xs the title block has no max-width, so it uses the width left after padding. It still only occupies the top of the screen. The middle of the forest stays clear. From sm up, the max-width pulls the paragraph back into a column. lg, xl, and xxl share one row: the scene tiers differ, the overlay does not.

Add the safe area to the action’s bottom padding so a phone home indicator does not cover the sentence:

padding-bottom: max(1rem, env(safe-area-inset-bottom));

Use the row’s own padding in place of 1rem at each breakpoint. env(safe-area-inset-bottom) is 0 on a desktop, so this line does not move the hint there.

Build steps

  1. Add storyText.js with the panel 1 chapter above. Include action only when the table says to keep the bottom row.
  2. Add StoryChapter and Action. Action looks up the icon name and renders nothing when action is missing.
  3. Render StoryOverlay as a sibling of <Experience />. Pass chapters[0]. Do not mount it inside <Canvas>.
  4. Fix the overlay to the viewport and set pointer-events: none. Pin Action to the bottom-left. Keep the icon beside the sentence.
  5. Write media queries at max-width: 575px, max-width: 767px, and min-width: 992px, using the padding, type size, max-width, and icon size in the table. Let md be the base styles between 768 and 991.
  6. Pad the action with max(…, env(safe-area-inset-bottom)).

Quiz

1. The “1” on “Enter the forest” in storyboard-2.png is:

Every cell has a number. The scene heading is “Enter the forest”.

2. StoryChapter and Action belong:

Screen copy stays fixed while the orbit moves the camera. A 3D text node would travel with the view.

3. pointer-events: none on the overlay:

The action row’s position is separate. pointer-events only decides who receives the swipe.

4. The round icon on an action row is:

The row is at the bottom of the panel. The icon and the sentence share one line, centered on each other.

5. Panels 5 and 6 have no bottom action because:

“Connect the trees” and “Watch the signal” already tell you what happens. action is omitted, and Action renders nothing.

6. The media queries must cut at 575, 767, and 992 because:

A different cut would resize the title while the segment count and dpr stayed on the previous tier. The rem values stay in CSS, not in storyText.js.
