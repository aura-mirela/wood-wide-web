Procedural track · GLB parts, InstancedMesh, placement matrices

Instancing scattered firs and mushrooms

What this lesson explains: what happens after the scatter helper returns a placement list. ScatteredFirTrees and ScatteredMushrooms do not choose points. They load a GLB, split it into parts, and draw one InstancedMesh per part at those placements.

The mask, the seed, and keepPlacementCandidateChance live in the previous lesson. This one starts from the array Terrain already computed.

Goal

After this lesson you should be able to:

  • say what a placement record contains, and what it does not contain;
  • explain why one GLB becomes several InstancedMesh objects;
  • walk the matrix loop: position, yaw, scale, part offset, setMatrixAt;
  • say why y is negated, and why the same index is used on every part;
  • name the one difference between the fir component and the mushroom component.

The two components are copies of one idea. Learn the fir file. The mushroom file is the same shape.

1. A placement is a transform, not a mesh

Each item in placements is a plain record:

{ x, y, elevation, rotationY, scale }
  • x, y — point on the terrain plane.
  • elevation — hill height from getTerrainElevation.
  • rotationY — yaw for this copy.
  • scale — size variety, 0.8 … 1.2.

No geometry, no material, no GLB. Terrain passes treePlacements into ScatteredFirTrees and mushroomPlacements into ScatteredMushrooms. The components only stamp models onto that list.

2. Read the GLB into part records

useGLTF loads the file and returns a scene. That scene is not mounted. It is a source of meshes. A useMemo walks it once and caches an array of plain records, one per mesh:

scene.updateMatrixWorld(true)
scene.traverse((child) => {
  if (!child.isMesh) return

  meshes.push({
    geometry: child.geometry,
    material: child.material,
    localMatrix: child.matrixWorld.clone(),
  })
})

For the fir, that array is two records: trunk, then foliage.

[
  { geometry: trunkGeometry, material: trunkMaterial, localMatrix: trunkMatrix },
  { geometry: foliageGeometry, material: foliageMaterial, localMatrix: foliageMatrix },
]

updateMatrixWorld(true) runs first because this scene is never added to the canvas, so the renderer will not refresh it. matrixWorld is where that part sits inside the file. The foliage matrix is what keeps the leaves on the trunk. If you skip the update, matrixWorld can still be the identity and every part instances at the model origin.

useGLTF.preload(url) at the bottom of the file starts the download when the module is imported, before the component renders. It does not create meshes.

3. One InstancedMesh per part

return parts.map((part, index) => (
  <InstancedTreePart
    key={index}
    geometry={part.geometry}
    material={part.material}
    localMatrix={part.localMatrix}
    placements={placements}
  />
))

This returns an array of React elements. For the fir: one element for the trunk, one for the foliage. index here is the part index (0 trunk, 1 foliage), used only as the React key.

Each InstancedTreePart renders:

<instancedMesh args={[geometry, material, placements.length]} />

geometry and material are the objects taken from the GLB. They are not rebuilt. placements.length is how many copies to allocate. A normal GLB mesh can draw itself once. An InstancedMesh can draw that same geometry many times, one matrix per copy.

The mushroom file has three meshes (cap, stem, annulus), so it mounts three InstancedMushroomPart elements. Same placements array on every part.

4. Write one matrix per copy

The <instancedMesh> starts with identity matrices: every copy at the origin. A useLayoutEffect fills the buffer before the first draw, so you never see a one-frame pile at the origin. useEffect would run after that paint.

placements.forEach((placement, index) => {
  dummy.position.set(placement.x, placement.elevation, -placement.y)
  dummy.rotation.set(0, placement.rotationY, 0)
  dummy.scale.setScalar(placement.scale)
  dummy.updateMatrix()
  composed.multiplyMatrices(dummy.matrix, localMatrix)
  mesh.setMatrixAt(index, composed)
})
  • dummy is a scratch Object3D. You reuse it so you do not allocate one object per tree.
  • Position (x, elevation, -y). The ground mesh is rotated -90° on X, and these instances are siblings of that mesh, so they do not inherit the rotation. A -90° turn around X maps local (x, y, z) to world (x, z, -y). Height becomes up. The minus sign keeps the forest on the same side of the plane as the hills and the mask.
  • Rotation is yaw only. X and Z stay 0 so the trunk stays upright.
  • updateMatrix() bakes position, rotation, and scale into dummy.matrix. That is the placement transform.
  • composed is that placement multiplied by localMatrix. The part offset is applied first, then the tree is moved onto the hill. composed means “both transforms already combined,” not a third kind of matrix.
  • setMatrixAt(index, composed) stores it. This index is the copy, not the part. Index 1 on the trunk and index 1 on the foliage are the same fir. Only localMatrix differs, so the foliage stays on that trunk.

Then:

mesh.instanceMatrix.needsUpdate = true
mesh.computeBoundingSphere()

needsUpdate uploads the matrix buffer to the GPU. computeBoundingSphere() rebuilds the sphere used for frustum culling. Without it, the sphere still describes one model at the origin. Orbit away from the origin and Three.js skips the whole forest even though trees are in front of the camera.

5. The mushroom difference

ScatteredMushrooms uses the same loop. One line changes:

dummy.scale.setScalar(placement.scale * MUSHROOM_BASE_SCALE)

MUSHROOM_BASE_SCALE is 0.0035. The Sketchfab file is about 127 units tall. placement.scale is only the 0.8–1.2 variety. Without the base scale, each “mushroom” is a building. The fir file is already near the right size, so it uses placement.scale alone.

Build steps (from this codebase)

  1. Load the GLB with useGLTF. Preload the URL at module scope.
  2. Force updateMatrixWorld(true), then collect { geometry, material, localMatrix } for every mesh.
  3. Render one InstancedMesh per part, with args={[geometry, material, placements.length]}.
  4. In useLayoutEffect, write (x, elevation, -y), yaw, and scale, multiply by localMatrix, and setMatrixAt.
  5. Set instanceMatrix.needsUpdate and recompute the bounding sphere.
  6. If the asset is huge, multiply by a base scale. Measure the bbox before you scatter.

Exercises

  1. Remove the minus on placement.y. Predict that the forest mirrors across X relative to the hills. Put it back.
  2. Skip multiplyMatrices and call setMatrixAt(index, dummy.matrix). Trunk and foliage should stack at the same origin inside each tree.
  3. Comment out computeBoundingSphere(). Orbit until the origin leaves the view. The trees should vanish together.
  4. Log parts.length for the fir and for the mushroom. You should see 2 and 3.
  5. Set MUSHROOM_BASE_SCALE to 1 for one reload. Confirm the mushrooms dwarf the terrain, then restore 0.0035.

Quiz

1. treePlacements stores:

The list is data. Geometry and material stay on the GLB parts and are shared by every copy.

2. parts.map in ScatteredFirTrees returns:

Two meshes in the file means two elements. Each element then draws every copy of that one part.

3. Index 1 on the trunk mesh and index 1 on the foliage mesh are:

Both parts walk the same placements array. The React key on InstancedTreePart is a different index: which part, not which tree.

4. dummy.position.set(x, elevation, -y) negates y because:

Local (x, y, elevation) becomes world (x, elevation, -y). Drop the minus and the forest mirrors across X.

5. computeBoundingSphere() after setMatrixAt:

Culling tests one sphere per InstancedMesh. A stale sphere hides the whole part at once.
