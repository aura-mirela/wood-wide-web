Terrain PBR textures, color space, and tiling

What this lesson explains: how TerrainPBRMaterial loads the pine-root maps, why the load callback calls configureTerrainTexture, what SRGBColorSpace and LinearSRGBColorSpace change, and why the repeat count lives in a useLayoutEffect instead.

Goal

After this lesson you should be able to:

  • name the five maps and which material slot each one fills;
  • say what configureTerrainTexture writes onto a texture;
  • choose SRGBColorSpace or LinearSRGBColorSpace for a new map and say why;
  • explain why wrap and color space are set in the useTexture callback;
  • explain why tiling is applied in useLayoutEffect.

These maps shade the soil. They are not the scatter masks. The masks stay off the material and only decide where firs and mushrooms may live.

1. Five files, five slots

const [albedo, ao, height, normal, roughness] = useTexture(
  TERRAIN_TEXTURES,
  (maps) => { /* configure each map */ },
)

useTexture loads every URL and returns THREE.Texture objects in the same order as the array. The names are yours. Drei does not know that the second file is ambient occlusion.

2. What configureTerrainTexture does

function configureTerrainTexture(texture, colorSpace) {
  texture.wrapS = RepeatWrapping
  texture.wrapT = RepeatWrapping
  texture.colorSpace = colorSpace
  texture.needsUpdate = true
}
  • wrapS / wrapT — what happens past the edge of the image. RepeatWrapping tiles it. The default, clamp, stretches the last pixel. Repeat is required before texture.repeat can tile.
  • colorSpace — how Three.js reads the numbers in the file. Passed in per map. See the next section.
  • needsUpdate — the texture already exists; this flags WebGL to pick up the new wrap mode and color space.

3. SRGBColorSpace and LinearSRGBColorSpace

PNG bytes are not automatically “color.” Three.js must be told whether to gamma-decode them.

SRGBColorSpace means “these bytes are an sRGB picture.” Mid-gray in the file is not halfway in light energy. Three.js converts the texel to linear light before shading. Use this for maps a person painted as color. In this material that is only the albedo.

LinearSRGBColorSpace means “these bytes are data. Do not gamma-correct them.” A stored 0.5 stays 0.5. Use this for:

  • AO — a darkening weight;
  • height — a bump amount;
  • normal — a direction, encoded in the RGB channels;
  • roughness — a 0–1 material parameter.

If you mark roughness as sRGB, lighting treats a mid value as darker than the texture author stored, and the soil looks uniformly too shiny or too matte. If you mark albedo as linear, the color looks washed out, because the shader skips the sRGB decode the artist expected.

The callback applies that split:

configureTerrainTexture(albedoMap, SRGBColorSpace)
configureTerrainTexture(aoMap, LinearSRGBColorSpace)
configureTerrainTexture(heightMap, LinearSRGBColorSpace)
configureTerrainTexture(normalMap, LinearSRGBColorSpace)
configureTerrainTexture(roughnessMap, LinearSRGBColorSpace)

4. Why a callback on useTexture

The second argument is drei’s onLoad callback. It runs when the textures have finished loading, including when they come from drei’s cache, and it receives the loaded textures.

Wrap mode and color space are set there, not in the component body, for two reasons:

  • Assigning texture.colorSpace during render is a side effect. Render should describe the material, not mutate Three.js objects on every pass.
  • The first frame would otherwise sample the maps with the loader defaults: clamp wrapping and the wrong color space. The ground would flash, then correct itself.

The callback runs once per load. It is the right place for settings that belong to the file. It is the wrong place for tiling, which is a prop and can change later.

5. useLayoutEffect sets the repeat

useLayoutEffect(() => {
  ;[albedo, ao, height, normal, roughness].forEach((texture) => {
    texture.repeat.set(tiling, tiling)
  })
}, [albedo, ao, height, normal, roughness, tiling])

tiling of 8 draws each map eight times along U and eight times along V. The same number on every map keeps the pine roots aligned. Terrain owns that number and passes it in. This component only applies it.

useLayoutEffect runs after React commits the material and before the browser paints. The first frame already has repeat 8. A useEffect would paint once at the default repeat of 1, then jump. Doing the write in the function body would mutate textures during render.

The dependency list re-runs the effect when tiling changes or when the texture objects change. The leading ; is only syntax: it stops the line [albedo, ...].forEach from being parsed as a continuation of the previous statement.

Repeat does nothing useful until wrap is RepeatWrapping. That is why wrap is set in the load callback, and the repeat count is set here.

Build steps (from this codebase)

  1. List the five PNG URLs in one array, in slot order.
  2. Write configureTerrainTexture: repeat wrap, a color space argument, needsUpdate.
  3. Pass that function from the useTexture callback. Albedo gets SRGBColorSpace. The four data maps get LinearSRGBColorSpace.
  4. In useLayoutEffect, set texture.repeat from the tiling prop on all five textures.
  5. Return meshStandardMaterial with map, aoMap, normalMap, roughnessMap, and bumpMap.

Exercises

  1. Set the albedo color space to LinearSRGBColorSpace. The soil color should look washed out. Put SRGBColorSpace back.
  2. Set the roughness map to SRGBColorSpace. Watch the highlight change, then restore linear.
  3. Pass tiling={2} from Terrain. The roots should get larger. Restore 8.
  4. Comment out RepeatWrapping and keep repeat.set(8, 8). The tiling should stop working. Restore the wrap.
  5. Remove the uv2 clone in createTerrainGeometry. AO should stop lining up. Put the clone back.

Quiz

1. configureTerrainTexture sets:

The repeat count is a separate step, because tiling can change after load.

2. Albedo uses SRGBColorSpace because:

Roughness, AO, height, and normals stay in LinearSRGBColorSpace so their stored numbers are not treated as color.

3. The useTexture callback runs:

The hook still returns the five textures. The callback is the onLoad hook.

4. Repeat is set in useLayoutEffect so that:

useEffect would allow one frame at repeat 1. The load callback would not rerun when tiling changes.

5. Marking the roughness map as SRGBColorSpace:

Roughness is a 0–1 parameter. sRGB decode changes that number before the lighting model sees it.
