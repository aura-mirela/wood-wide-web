Terrain geometry, noise, and FBM

What this lesson explains: how this project builds the ground. A flat plane already has vertices. A noise function supplies one height number per point. Fractal Brownian motion stacks that noise into hills. getTerrainElevation is the public height query so trees and mushrooms sit on the same hills as the mesh.

Goal

After this lesson you should be able to:

  • say what PlaneGeometry already contains before any displacement;
  • explain what noise2D returns, and what it does not return;
  • walk one FBM octave: frequency doubles, amplitude halves;
  • explain why getTerrainElevation exists beside the geometry loop;
  • name the three steps after the height loop: update the buffer, recompute normals, copy uv to uv2.

Terrain does not displace vertices itself. It asks createTerrainGeometry() once and hands that PlaneGeometry to the ground mesh.

1. The plane starts full, and flat

const geometry = new PlaneGeometry(size, size, segments, segments)
const positions = geometry.attributes.position

Defaults in this project: TERRAIN_SIZE = 20, TERRAIN_SEGMENTS = 256.

segments is the number of quads along one edge, not the number of vertices. Vertices are segments + 1, so this grid is 257 × 257 points (66,049 vertices). positions is already filled when you read it. It is not an empty buffer you push into.

A Three.js plane lies in the XY plane and is centered on the origin:

  • x and y run from -size/2 to +size/2 (here -10 to 10);
  • z is 0 on every vertex. The ground is still a tabletop.

The mesh in Terrain.jsx is later rotated [-Math.PI / 2, 0, 0]. That rotation lays local Z (height) onto world Y. The geometry function itself does not rotate anything. It only writes height into local z.

2. What noise2D is

noise2D(x, y) in src/lib/noises/noise2D.js is a JavaScript port of Ashima’s 2D simplex noise. You do not tune the constants at the top of that file (C, mod289, permute). They are the published kernel: a grid hash, a smooth falloff, a gradient contribution. The useful contract is small:

  • Input: a point in 2D. Here that point is a place on the plane (or a scaled version of it).
  • Output: one number, roughly in -1 … 1. Not a new (x, y). Not a vertex. Not a color.
  • Smooth: nearby inputs give nearby outputs, so hills do not sparkle from pixel to pixel.
  • Repeatable: the same (x, y) always returns the same number. There is no seed in this file. The hills are the same every reload.

One octave of raw noise looks like gentle, similar-sized bumps. Real ground has big ridges and small wrinkles. That stacking is FBM, not the noise function.

3. FBM stacks five octaves

Fractal Brownian motion here means: sample the same noise several times, each time at a higher frequency and a lower amplitude, and add the samples.

function fbm(x, y, frequency, amplitude) {
  let value = 0
  let amp = amplitude
  let sampleX = x * frequency
  let sampleY = y * frequency

  for (let i = 0; i < 5; i++) {
    value += amp * noise2D(sampleX, sampleY)
    sampleX *= 2
    sampleY *= 2
    amp *= 0.5
  }

  return value
}

Defaults: TERRAIN_FREQUENCY = 0.1, TERRAIN_AMPLITUDE = 0.25. Five passes:

PassWhat changesWhat you see
0sample at 0.1×, weight 0.25the broad hills
1frequency ×2, amplitude ×0.5ridges on those hills
2–4same rule, three more timessmaller and smaller wrinkles

Frequency is how zoomed-in the noise is. Higher frequency → more bumps across the same 20-unit plane. Amplitude is how tall that pass is allowed to be. Halving it each pass keeps the small wrinkles from overpowering the big shape. This is often called lacunarity 2 and gain 0.5. This file just writes *= 2 and *= 0.5.

The return value is still one height, the sum of the five weighted noises. It is the number that will be stored as z.

4. getTerrainElevation is FBM with the terrain defaults

export function getTerrainElevation(x, y, frequency = TERRAIN_FREQUENCY, amplitude = TERRAIN_AMPLITUDE) {
  return fbm(x, y, frequency, amplitude)
}

It does not build a mesh. It does not return coordinates. x and y are inputs (“how high is the ground here?”). The return is the FBM height at that plane point.

The geometry loop could call fbm directly, and it does. Scatter cannot, unless it imports a private function. getTerrainElevation is the public door, locked to the same frequency and amplitude as the mesh. If those two ever diverge, trees float or sink through the hills.

Scatter points are usually between vertices. You cannot look up “vertex 4827.” You evaluate the same function at the candidate’s (x, y). Because noise is continuous, that height matches the surface the triangles draw.

5. Writing height, then normals, then uv2

for (let i = 0; i < positions.count; i++) {
  const elevation = fbm(
    positions.getX(i),
    positions.getY(i),
    frequency,
    amplitude,
  )

  positions.setZ(i, elevation)
}

positions.needsUpdate = true
geometry.computeVertexNormals()
geometry.setAttribute('uv2', geometry.attributes.uv.clone())
  1. getX / getY — read the flat grid. Do not invent new vertices.
  2. setZ — replace the flat 0 with FBM height. x and y stay put.
  3. needsUpdate = true — tell Three.js the position buffer changed, so the GPU copy is refreshed.
  4. computeVertexNormals() — rebuild the normal attribute from the new triangles. A plane’s original normals all point along +Z. After hills, that would light the ground as if it were still flat. This is the recompute. It happens on the CPU, in this function, not in a shader.
  5. uv2 — PlaneGeometry already has uv (0–1 unwrap). MeshStandardMaterial reads the AO map from uv2, and albedo / normal / roughness / bump from uv. Cloning uv into uv2 makes the pine-root AO line up with the other maps. clone() matters so the two attributes do not share one buffer.

TerrainPBRMaterial never sees FBM. It only shades the geometry this function returned: color maps, plus a small bumpMap from the height texture for bark-scale detail. The big hills are already in the vertex positions.

6. Why this is JavaScript, not a vertex shader

A vertex shader could add FBM on the GPU every frame. This project does not. Height is baked once when the geometry is created, for two reasons that have to agree:

  • Normals. computeVertexNormals() reads positions on the CPU. If the shader moved vertices afterward, those normals would still describe the flat plane.
  • Scatter. getTerrainElevation is CPU code. It can only match the mesh if the mesh used the same CPU function.

Terrain caches the result:

const geometry = useMemo(() => createTerrainGeometry(), [])
useEffect(() => () => geometry.dispose(), [geometry])

Empty deps means “build once per mount.” dispose frees the GPU buffers when Terrain unmounts. The hills do not animate, so there is nothing to recompute per frame.

Build steps (from this codebase)

  1. Put simplex noise2D in src/lib/noises/noise2D.js. Prove one call returns a finite number, and the same inputs return the same number.
  2. Write fbm with 5 octaves, *= 2 and *= 0.5.
  3. Export getTerrainElevation with the terrain frequency and amplitude as defaults.
  4. Create a PlaneGeometry, set each z from fbm(x, y), then computeVertexNormals().
  5. Clone uv to uv2 so the PBR AO map has a UV set.
  6. Cache that geometry in Terrain and rotate the mesh -90° on X when you draw it.

Exercises

  1. Log positions.getZ(0) before the loop and after. Before must be 0. After must be the FBM value.
  2. Temporarily set the loop to 1 octave (change 5 to 1). The ground should look like one scale of bumps. Put 5 back.
  3. Double TERRAIN_FREQUENCY only. Predict more bumps across the same 20-unit square, not taller mountains. Then try doubling TERRAIN_AMPLITUDE instead.
  4. Comment out computeVertexNormals(). The hills stay, but the lighting goes flat. Write one sentence about why.
  5. Call getTerrainElevation at a vertex’s (x, y) and compare it to that vertex’s z. They must match.

Quiz

1. Right after new PlaneGeometry(20, 20, 256, 256), the position attribute:

segments counts quads. Vertices are segments + 1. FBM overwrites z; it does not create the grid.

2. noise2D(x, y) returns:

Simplex noise is one sample. FBM is the function that calls it five times and adds them.

3. Each FBM octave in this file:

sampleX *= 2 and amp *= 0.5. Higher frequency, smaller height.

4. getTerrainElevation(x, y) is used by scatter because:

The return value is one height (local z). The instance later places the object at (x, elevation, -y).

5. geometry.computeVertexNormals() must run after setZ because:

Normals are derived from the triangles. If you compute them before displacement, they describe the tabletop.
